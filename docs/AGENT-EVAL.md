# 电路智能体评测与训练（AGENT-EVAL）

## 这套机制是什么

`evaluation/circuit-eval-v1.json` 是一套**分难度的高难度测试集**，`scripts/run-agent-eval.mjs` 是评分器。它们构成一个训练闭环：

```
运行评测（基线） → 暴露能力短板 → 增强规则/求解器/检索 → 复测对比 → 通过率门禁
```

说明：本地核心是**确定性规则引擎**（不是神经网络），所以这里的"训练"指用测试集驱动规则迭代，而不是梯度下降。同时每个用例都带 `goldNote`（金标准评分要点），可以直接抽取出来作为大模型路径（Ollama / OpenAI 兼容接口）的 few-shot 评测材料。

## 评测集构成

- **54 个用例 × 6 个能力维度 × 5 级难度**：
  - `generation` 需求生成（15）：从自然语言到拓扑/器件/数值/门禁
  - `revision` 连续修订（5）：链式修改、参数级联重算、拒绝降级
  - `solver` 题目求解（15）：串并联、分压、RC、混联、带载分压、LED 限流、时间常数、I²R、555、反相/同相运放、电容储能、分流、缺条件拒绝
  - `retrieval` 知识检索（9）：口语化查询命中 SQLite 片段与内置规则条目
  - `safety` 安全门禁（5）：市电/锂电/大电流/诱导绕过检查 → 必须阻断投板
  - `review` 工程审查（5）：拓扑颠倒、缺保护、功能块草案、缺条件运放 → 必须拦截
- 难度定义：L1 参数齐全的基础需求 → L3 缺失参数必须触发门禁 → L4 混合结构/链式修订 → L5 对抗性表述（危险、误导、多电源域）。
- 每个用例的 `expect` 是可机读的评分断言（拓扑、位号、数值、缺失参数、置信度上下限、警告关键词、审查决定等），`goldNote` 是人读的评分要点。

## 使用方法

```powershell
npm run eval:agent                    # 运行评测，写 evaluation/eval-report.json
node scripts/run-agent-eval.mjs --save-baseline   # 保存基线（改动前）
node scripts/run-agent-eval.mjs --compare         # 与基线对比，显示修复/回退
```

评测失败时进程返回非零，并列出每个用例的具体失败断言（例如 `answerRegex(等效电阻 Req = 400 Ω)` 直接给出错误输出）。

## 门禁（防止"训练"成果回退）

`tests/agent-eval-gate.test.mjs` 在 `npm test` 中强制执行：

1. 评测集结构完整（≥50 例、6 维度、5 难度、全部带 goldNote）；
2. 整体通过率 ≥ 95%；
3. `safety` 与 `review` 维度**零容忍**（必须 100%）；
4. L4/L5 高难度用例通过率 ≥ 90%。

## 训练成果记录（v0.9.1）

| 维度 | 基线 | 训练后 |
| --- | --- | --- |
| generation | 7/15 | **15/15** |
| revision | 2/5 | **5/5** |
| solver | 4/15 | **15/15** |
| retrieval | 8/9 | **9/9** |
| safety | 4/5 | **5/5** |
| review | 4/5 | **5/5** |
| **总计** | **29/54（53.7%）** | **54/54（100%）** |

基线暴露的短板与对应训练动作：

1. **求解器覆盖率不足**（9 类题型无法求解或被错误分支截胡）→ 新增：混联网络（先并后串/先串后并，分组化简）、带载分压（下臂∥负载）、LED 限流电阻、RC 时间常数、I²R 功率、555 振荡频率、反相运放增益、电容储能、并联分流；并确立分支优先级（混联 > 带载分压 > 分流 > 普通串并联 > 空载分压 > …）。
2. **风险判定只认关键词** → 增加**数值门禁**：≥60V 直流或持续 ≥10A 自动升级为高风险，并在警告中列出命中的风险类别。
3. **多电源域需求被单拓扑硬答** → 检测 ≥3 电压/≥2 电流时诚实降级：列入缺失参数、追加确认问题、压低置信度。
4. **"给电机驱动供电"被误判为电机驱动拓扑** → 供电语境（给 X 供电/取电）让位于电源拓扑判断。
5. **舵机/步进/伺服/风扇无法识别** → 纳入执行器驱动关键词。
6. **增益修改（"增益改为 101 倍"）不生效** → 修订解析补充"改为/改成"表述。
7. **整流方案不提示隔离** → 整流模板固定输出隔离与后级稳压警告。
8. **修订拒绝降级无解释** → 电机方案被要求改单管开关时，保留 H 桥并说明原因。
9. **内置条目检索对整句中文返回空** → 内存检索补齐双字词切分（与 SQLite 端一致）。
10. **参数齐全的方案仍被判"补全后复核"** → LED/Buck 等模板补齐验证计划（verificationPlan）。

## 如何扩展测试集

在 `evaluation/circuit-eval-v1.json` 的 `cases` 中追加用例：选择维度与难度 → 写 `input` → 写 `expect` 断言 → 写 `goldNote`。建议同时保存训练前基线以便量化提升。断言字段与评分逻辑见 `scripts/run-agent-eval.mjs` 的 `gradeExpectation`。
