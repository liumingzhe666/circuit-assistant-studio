# AI 接入说明

## 智能体 RAG 检索（0.9.0）

生成、修订与解答任务开始时，智能体会对本地 SQLite 知识库执行多路召回检索：

1. **路线 1 · 原始查询**：需求原文的 CJK 双字词与英文词元。
2. **路线 2 · 同义扩展**：领域同义词表（约 100 组）把口语说法映射为资料术语，例如“小车马达堵转”会扩展出 H桥、stall、启动电流。
3. **路线 3+ · 主题专项路由**：按关键词命中选择专项路线（Buck/Boost/LDO/电机驱动/LED/运放/ADC/MCU/PCB 载流/浪涌保护/热设计/EMI/电池安全/555/滤波），每条路线检索该主题的工程关键词。
4. **RRF 融合**：各路线按倒数排名（1/(60+rank)）融合，再叠加权威层级（A+/A）、bm25 归一化分与整词命中奖励。
5. **逐源限流**：同一来源的片段数量受档位上限约束，避免单一文档垄断上下文。

检索强度分三档（设置页与知识中枢可切换，默认“深度”）：

| 档位 | 每路候选池 | 返回条数 | 逐源上限 | 主题路由 |
| --- | --- | --- | --- | --- |
| 标准 standard | 24 | 8 | 3 | 关闭 |
| 深度 deep | 48 | 12 | 3 | 开启 |
| 穷尽 exhaustive | 90 | 18 | 4 | 开启 |

`searchWithTrace(query, options)` 返回 `{ hits, trace }`：trace 包含每条路线的词元与命中数、同义扩展清单、候选与选出数量、耗时，用于界面上的“检索过程”面板与方案页的检索摘要。IPC 通道：`knowledge:search`（兼容旧格式，只返回 hits）与 `knowledge:search-debug`（返回 hits + trace）。

## Ollama 本地接口

默认地址：`http://127.0.0.1:11434`

软件调用：

- `GET /api/tags`：检测服务和模型列表。
- `POST /api/chat`：文本方案增强与图片识别。
- 图片以 base64 传给支持视觉输入的模型。
- 请求使用低温度（默认 0.15，可调）、JSON 输出、显式 `num_ctx` 上下文窗口（默认 8192，可调），并在 90 秒后超时。

本地模式不会主动安装或下载模型。这样可以让用户明确控制磁盘空间、模型许可证和下载流量。

## OpenAI 兼容接口

软件调用：

- `GET {baseUrl}/models`：连接测试。
- `POST {baseUrl}/chat/completions`：文本或视觉消息。
- 图片按 `image_url` data URL 格式提交。
- 请求温度与本地模型共用同一设置。

远程接口必须是 HTTPS；只有本机环回地址允许 HTTP。API Key 会加密保存在系统用户目录，不写入项目源码。

## 提示词体系（0.9.0）

- **工程审阅系统提示词**：定义审阅协议——意图与拓扑匹配、证据分级（数据手册 > 厂商应用笔记/标准 > 教科书公式 > 经验假设）、最坏工况清单、安全门禁（市电/高压/锂电/大电流阻断）、unknown 标记纪律。
- **领域审查指南**：按电路族（开关电源、LDO、电机/H桥、LED、模拟、MCU、接口、PCB、安全）注入“必查项”清单，让通用模型获得电路专家的检查视角。
- **RAG 引用纪律**：注入的知识片段要求模型在 `knowledgeCitations` 中写明标题、页码与支持的具体判断；资料冲突时优先权威层级高者。
- **视觉与解题提示词**：结构与功能结论分离、模糊文字不得猜成型号、缺失条件不得假设。

### 结果协议增强

方案增强在原有字段上新增 `topologyAssessment`（拓扑与需求匹配的判断）；`mustConfirm` 的问题要求具体、可直接回答。

## 本地 SQL 书籍知识

“知识中枢”导入的合法本地资料会写入 SQLite FTS5。生成或修订电路时先执行多路召回检索，再把相关片段交给模型，并要求模型按书名与页码引用。该流程是 RAG，不会重新训练或修改模型权重。

为避免本地书籍内容外传，检索片段默认只发给 Ollama 或 `localhost` / `127.0.0.1` / `::1` 上的兼容接口。如需发送到远程模型，必须在“AI 与设置 → 知识检索与上下文”中显式开启“允许把本地知识片段发送到远程模型”，默认关闭。数据库结构、位置与 SQL 示例见 [LOCAL-KNOWLEDGE-SQL.md](LOCAL-KNOWLEDGE-SQL.md)。

## 结果协议

视觉识别要求模型返回：

```json
{
  "circuitType": "候选电路类别",
  "function": "功能说明",
  "confidence": 0.0,
  "blocks": [],
  "components": [],
  "signalFlow": "",
  "evidence": [],
  "uncertainties": [],
  "risks": [],
  "nextSteps": []
}
```

模型输出会作为候选分析展示；后续版本应增加 JSON Schema 验证、元件与网络交叉验证及多模型一致性检查。
